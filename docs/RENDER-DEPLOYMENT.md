## Prerequisites Before Deployment

1. A verified [Render Account](https://dashboard.render.com).
2. A GitHub account with access to your ERP/MES repository.
3. Clean local branch with all tests passing (verified in repository).

## Step-by-Step Deployment Instructions

### Step 1: Push Code to GitHub

From your repository root:
```bash
git status
git add .
git commit -m "chore: prepare production deployment for Render"
git push origin main
```
*(Replace `main` with your active production branch if different).*

---

### Step 2: Open Render & Create Blueprint

1. Navigate to the **[Render Dashboard](https://dashboard.render.com/)**.
2. Click **New +** (top right button).
3. Select **Blueprint** from the dropdown menu.
4. Connect your GitHub account (if not already connected) and select your repository:
   - Repository: `Project_10(Apparel-Textile ERP+MES-platform)`
5. Render detects the root `render.yaml` automatically.
6. Provide a Blueprint name (e.g., `textile-erp-production`).
7. Select your preferred deployment region (e.g., `Oregon (US West)`, `Frankfurt (EU)`, or `Singapore (Southeast Asia)`).
   > [!NOTE]
   > Keep PostgreSQL, API, and Web in the same region for optimal internal network performance and zero data transfer egress fees.

---

### Step 3: Configure Environment Variables

Render inspects `render.yaml` and presents the list of resources to create:
1. **`erp-mes-postgres`**: PostgreSQL 16 database.
2. **`erp-mes-api`**: NestJS web service.
3. **`erp-mes-web`**: Next.js web service.

You will be prompted for variables configured with `sync: false`:

#### For `erp-mes-api`:
- **`DATABASE_URL`**: Handled automatically via `fromDatabase` reference.
- **`JWT_SECRET`**: Automatically generated by Render (`generateValue: true`).
- **`JWT_REFRESH_SECRET`**: Automatically generated by Render (`generateValue: true`).
- **`FRONTEND_URL`**: Enter the expected URL of your frontend service (e.g., `https://erp-mes-web.onrender.com`).
- **`CORS_ALLOWED_ORIGINS`** (Optional): Additional permitted domains (e.g., custom domain).

#### For `erp-mes-web`:
- **`NEXT_PUBLIC_API_URL`**: Enter the API URL (e.g., `https://erp-mes-api.onrender.com/api/v1` or `https://erp-mes-api.onrender.com`).

Click **Apply**.

---

### Step 4: Automated Build & Startup Sequence

Render provisions and builds the services in sequence:
1. **Database Provisioning**:
   - `erp-mes-postgres` starts up and assigns internal and external connection credentials.
2. **API Build & Migration Deployment**:
   - Render runs:
     ```bash
     pnpm install --frozen-lockfile && pnpm --filter @textile-erp/database run db:generate && pnpm --filter api run build
     ```
   - Render executes startup command:
     ```bash
     pnpm --filter @textile-erp/database run db:deploy && node apps/api/dist/main.js
     ```
   - All 6 Prisma migrations deploy cleanly to create all 83 database models.
   - NestJS binds to `0.0.0.0:$PORT`.
   - Render verifies health probe: `GET /health` returns HTTP 200.
3. **Frontend Build & Startup**:
   - Render runs:
     ```bash
     pnpm install --frozen-lockfile && pnpm --filter web run build
     ```
   - Next.js pre-renders all 45 production routes.
   - Render executes startup command:
     ```bash
     pnpm --filter web run start -- -p 10000 -H 0.0.0.0
     ```
   - Health check probe: `GET /` returns HTTP 200.

---

### Step 5: Initialize Production Master Data & RBAC

Once the API and database are running, initialize the core platform permissions and create your production admin tenant:

1. In Render Dashboard, click **erp-mes-api**.
2. Click the **Shell** tab on the left sidebar.
3. Run the production seed command:
   ```bash
   # Initialize global permissions only:
   pnpm run db:seed:prod
   ```
4. If you want to initialize a tenant and admin account at the same time:
   ```bash
   INIT_TENANT_ID="tenant-apex-1" \
   INIT_TENANT_NAME="Apex Textiles Ltd" \
   INIT_ADMIN_EMAIL="admin@apextextiles.com" \
   INIT_ADMIN_PASSWORD="YourStrongPassword123!" \
   pnpm run db:seed:prod
   ```
   *(Or if you prefer to seed demo mock data for evaluation, run `pnpm run db:seed`).*

---

### Step 6: Post-Deployment Smoke Verification

Execute the following sanity verification:

1. **Verify Health Endpoints**:
   - Open browser or terminal:
     ```bash
     curl -i https://YOUR-API-NAME.onrender.com/health
     # Expected: HTTP 200 {"status":"UP", ...}
     curl -i https://YOUR-API-NAME.onrender.com/ready
     # Expected: HTTP 200 {"status":"READY", ...}
     ```
2. **Verify Frontend Loading**:
   - Navigate to: `https://YOUR-WEB-NAME.onrender.com/login`
   - Confirm styled dark UI loads without blank screen or console errors.
3. **Verify Authentication & Tenant Isolation**:
   - Log in with initialized admin credentials.
   - Confirm token acquisition and redirection to `/dashboard`.
4. **Verify Representative Business Modules**:
   - **MDM**: Navigate to Styles, Buyers, Factories.
   - **Costing**: Verify costing sheets listing.
   - **Production Planning**: Inspect Production Orders.
   - **MES Floor Execution**: Check Bundle scanning / Production line monitoring.
   - **Quality**: Check 20 standard apparel defects catalog.
   - **Inventory / Material**: View GRNs, fabric rolls, stock audit.
   - **Packing / Warehouse**: Check cartons and warehouse bin layout.
   - **Shipping**: Check shipments, commercial invoices, gate passes.
   - **Bulk Data Import / Export**: Verify entity schemas and CSV template downloads.

## Operational Monitoring & Maintenance

### How to Inspect API Logs
1. Render Dashboard → **erp-mes-api** → **Logs**.
2. Logs are streamed live via Pino with structured JSON formatting. Sensitive credentials (`password`, `authorization` headers) are automatically redacted.

### How to Inspect Frontend Logs
1. Render Dashboard → **erp-mes-web** → **Logs**.
2. Displays SSR requests, page generation metrics, and runtime exceptions.

### How to Redeploy After Code Changes
- Pushing to your production GitHub branch triggers an automatic zero-downtime redeploy.
- To trigger manually: Render Dashboard → Select Service → **Manual Deploy** → **Deploy latest commit**.

### How to Roll Back
1. Render Dashboard → Select Service → **Deploys**.
2. Find the previous successful deployment.
3. Click the three dots `...` next to the deployment → **Rollback to this deploy**.

### Critical Database Rules: What NOT to Do
- **NEVER** run `prisma db push` against the production database.
- **NEVER** run `prisma migrate reset` against production (will destroy all data).
- **NEVER** edit PostgreSQL schema tables directly without committing a Prisma migration.
